# Git sync status in the UI

## Summary
Make it obvious, from inside the app, when the local repo has work that isn't on GitHub
(uncommitted files, unpushed commits) and when GitHub has commits that aren't local (need a
pull). Joe works on this repo from more than one machine, so a stale checkout is the real
hazard.

## Design
- **Server (`server/git.ts`)** owns the status. `git status --porcelain=v2 --branch` gives
  branch, upstream, ahead/behind and changed files; `git log` lists the commit subjects.
- **Cadence:**
  - Local state (uncommitted / ahead) is re-read every 5s while a browser is connected. It is
    a local command, so this is cheap.
  - Remote state needs a `git fetch`. It runs on server start, every 5 minutes while a browser
    is connected, when the tab regains focus (at most once per minute), and on "Check now".
    Fetch is non-interactive (`BatchMode`), times out after 20s, and its error is shown.
- **Push to the browser:** status changes are broadcast over the existing `/ws` socket
  (`{type:'git'}`); `GET /api/git` and `POST /api/git/fetch` back it.
- **UI:** a pill in the top bar of every page: `✓ synced`, `● N uncommitted`, `↑ N to push`,
  `↓ N to pull` (combined when several apply). Click opens a panel listing the files, the
  commits each way, and when the remote was last checked, with a "Check now" button.
- Read-only: no pull/push/commit buttons in this iteration.
